## 遇到的问题与修正

- 手机首次 APK 安装要求系统指纹；由用户本人完成后安装成功。ADB 不代替安全验证。
- 安装期间 AstroBox 出现原生 SIGABRT / Rust IPC panic，两次队列记录丢失。后来系统反复请求目标手环蓝牙配对；手机侧确认后，用户在手环完成确认，恢复连接并看到数据。尚不能断言配对等待是原生崩溃的根因，也不能把 AstroBox 崩溃写成已由本项目修复。
- 初版手机只要读到电脑快照就显示“统计已同步”，无法区分设备是否收到。现在改为“电脑统计已读取”，手环成功应用数据后单独回执，再显示“手环已应用统计快照”。电脑持久记录白名单字段：事件类型、快照时间、设备版本码、电脑接收时间，不保存聊天内容。
- 增加“10 秒后发送测试提醒”，通过生产同一通知渠道发布明确标记的测试消息。留出锁屏时间；诊断消息不进入 Codex 完成事件队列、不生成完成 ACK，也不等同于所有真实任务来源已覆盖。
- 本次约 21:49 的诊断测试，手机为 Dozing，系统查询中只找到 PowerProfile 渠道的聚合记录，未找到独立测试 tag。此查询没有单独证明测试消息发布或送达；随后用户明确确认测试标题、收到通知并震动，因此将本次诊断链路记为通过。未将聚合记录解释成自动化设备回执，也未据此判断独立 tag 消失的原因。

互联网数据链路已取得设备回执，实际拔线刷新也已通过。后台回执是机器确认，不在手环生成系统通知或震动。通知须分别记录手机实际发布、手环送达及用户确认的物理震动；诊断通知不能冒充真实 Codex 完成。继续验收真实完成提醒、长时锁屏、离线重试和重启。公网令牌、实际统计和完整设备日志不进入公开记录。

## 手机 v15 后台与界面改进（待发布验收）

简洁的原生深色卡片状态页，主界面显示运行、手环、最近同步、米家控制和回执；低频维护选项折叠。启动页面立即拉起前台服务，不以手环连接成功为前提；保留 START_STICKY、开机和自身升级恢复。周期查询手环连接并清理断线监听，恢复网络时触发重连。后台使用独立同步、米家控制和更新任务，页面退出不停止服务。

新增忽略电池优化的用户设置入口、通知状态和厂商后台/自启动设置提示。没有常驻屏幕、无限唤醒锁或 Alarm 重启循环；用户强制停止后需重新打开，厂商省电限制和长时间 Doze 不可由构建或 START_STICKY 推断通过。每分钟最小运行回执只含随机会话、运行秒数、版本、最近同步/手环消息时间、连接与权限布尔值，不包含设备身份、账号、通知内容或聊天。

## 2026-11-19 v15 实测与恢复供电问题

用户确认已更新 v15。私有运行回执显示 phoneVersion=15、通知允许、电池优化豁免已开、手环连接；一次同会话报告已连续运行 435 秒。后续手机米家报告已采用 computer 正式绑定，手环实际快照回执 versionCode=15。此证据不代表全天后台或手机重启验收。

用户报告手环关供电正常，恢复供电后米家开关为开、功率约 5W，屏幕持续黑、按实体电源键才恢复，反复切换有时可启动。只读 Windows Kernel-Power 记录显示 03:02:07 失去 AC，03:02:14 进入 TargetState/EffectiveState=5（S4 休眠）；并非已验证的完全断电 G3。机型的 BIOS/EC 来电自启是否支持 S4、触发时序仍未核验，用户不记得 BIOS 选项原文。5W 可能是适配器待机/充电；不能仅凭功率确定具体部件或确认已启动。不把“米家开关为开”记为 Windows 唤醒成功，不用自动反复断电尝试修复。

## v16 电源交互修正（待发布/真机）

触控区 72×76、圆形按钮 56、图标 36；点击即时处理高亮和短震、对应命令成功/失败 UI 与震动、重复点击抑制和晚到/无关轮询保护。同步按钮也有短震，可在不操作插座时验证 vibrator。官方 Vela API 已声明，目标 10 Pro 的实际物理震动仍需用户确认。

手机接收命令立即回执，独立命令执行器不排在配置下载/周期读回/诊断上传之后；成功状态先到手环，诊断上传异步，不让中继网络失败抹掉已确认米家读回。周期读回按命令代次隔离，不能覆盖新命令结果。供电和电脑在线分开，恢复供电只显示待上线，需新电脑心跳后才显示在线；未上线不自动断电重试。

未修改 BIOS、C-state、Windows 供电/休眠配置，也未主动切换电脑插座。本轮硬件唤醒原因保留为待核验，不宣称 v16 修复 BIOS 唤醒。
